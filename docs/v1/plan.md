## P0：输入链路、建图和起点规划

1. 查world277的里程计发布/订阅、QoS、时钟、节点退出和进程残留。FAST-LIO日志已有点云保存，不能把采集侧零样本直接当算法无输出。
2. 将建图路径完成与有效地图分开：必须有LIO轨迹、地图包和有限指标；无输入及时退出，保留失败记录。
3. 查BARN11/55的地图可达性、起点/目标坐标、AMCL与footprint位置。先区分真实无路和接口错误，不直接换全局规划器。
4. 查BARN177的bt_navigator激活失败，区分节点退出、依赖未就绪与启动顺序，复用通用生命周期处理。
5. 查map2的LiDAR预测过期：发布间隔、处理耗时、队列和节点存活。保持新鲜度检查，修复生产/消费链路。

验收：277新建图有效；11/55严格导航成功；map2不再因输入过期退出；177的Nav2稳定激活并严格成功。若277单例不复现，加入短启动/关闭序列复现批次问题，单次通过不算修复完成。

## P1：动态避障与停车恢复

1. 回放warehouse obs10首次碰撞前的扫描、轨迹、预测、命令及控制/恢复状态。
2. 依据记录修复速度估计、轨迹确认/过期、短时预测与执行约束；预测不能只影响MPPI而忽略造成碰撞的旋转或恢复动作。
3. 定位144的停车原因及AMCL更新中断。该例最后AMCL位置误差约0.030m，但时间戳长期未更新；优先查卡死和新鲜度，不先认定定位漂移。
4. 对map2 obs10和BARN99回放控制、规划与恢复记录，确认无碰撞超时的共同原因；不直接沿用144的诊断。
5. 对已证实的停车/振荡/终点调整瓶颈做最小参数或逻辑修复。保留零碰撞与严格终态条件。

验收：warehouse obs10、map2 obs5/obs10、144、99严格成功；碰撞修复不能靠增大超时、缩小评估footprint或降低速度上限。
